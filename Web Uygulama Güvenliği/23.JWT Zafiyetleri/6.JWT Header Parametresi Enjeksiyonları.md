JWS (JSON Web Signature) spesifikasyonuna göre, yalnızca

alg

başlık parametresi zorunludur. Ancak, pratikte JWT başlıkları (JOSE başlıkları olarak da bilinir) sıklıkla birçok başka parametre içerir. Bu parametreler saldırganlar için özellikle ilgi çekicidir.

- **jwk (JSON Web Key):** Anahtarı temsil eden gömülü bir JSON nesnesi sağlar.
- **jku (JSON Web Key Set URL):** Doğru anahtarların içeren bir anahtar seti URL'si sağlar.
- **kid (Key ID):** Birden fazla anahtarın kullanıldığı durumlarda doğru anahtarı belirlemek için bir kimlik sağlar. Bu parametre, anahtarın formatına bağlı olarak 
    
    kid
    
     ile eşleşebilir.

Kullanıcı tarafından kontrol edilebilen bu parametreler, sunucuya imzayı doğrularken hangi anahtarı kullanması gerektiğini söyler. Bu bölümde, sunucunun gizli anahtarı yerine kendi anahtatırımızla imzalanmış ve değiştirilmiş JWT'lerin nasıl enjekte edebileceğini ele alacağız.

### JWK Parametresi ile Kendinden İmzalı JWT'leri Enjekte Etme

JWS spesifikasyonu, sunucuların genel anahtarlarını, JWK formatında doğrudan token içine gömmek için

jwk

başlık parametresinin kullanılabileceğini belirtir.

JWK Nedir?

JWK (JSON Web Key), anahtarları JSON nesnesi olarak temsil etmek için standartlaştırılmış bir formattır. İşte bu formata bir örnek:

```auto
{
    "kid": "ed2Nf8sb-sD6ng0-scs5390g-fFD8sfxG",
    "typ": "JWT",
    "alg": "RS256",
    "jwk": {
        "kty": "RSA",
        "e": "AQAB",
        "kid": "ed2Nf8sb-sD6ng0-scs5390g-fFD8sfxG",
        "n": "yy1wpYmffgXBxhAUJzHHocCuJolwDqql75ZWuCQ_cb33K2vh9m"
    }
}
```

Genel ve Özel Anahtarlar

İdeal olarak, sunucular yalnızca sınırlı bir genel anahtar (public key) listesini kullanmalıdır. Ancak, yanlış yapılandırılmış sunucular bazen

jwk

parametresinde gömülü herhangi bir anahtarı kullanabilir.

Saldırı Adımları

1. Burp Suite'in JWT Editor uzantısını yükleyin ve **JWT Editor Keys** sekmesine gidin.
2. Yeni bir RSA anahtarı oluşturun.
3. JWT içeren bir isteği Burp Repeater'a gönderin.
4. **JSON Web Token** sekmesine geçin ve token'in payload'unu istediğiniz gibi değiştirin.
5. **Attack** butonuna tıklayın ve **Embedded JWK** seçeneğini seçin. Oluşturduğunuz RSA anahtarını seçin.
6. İsteği sunucuya göndererek sunucunun nasıl yanıt verdiğini inceleyin.

Bu saldırıyı manuel olarak da gerçekleştirebilirsiniz. Ancak,

jwk

başlık parametresini eklerken, JWT'nin

kid

başlık parametresini gömülü anahtarın kid parametresiyle eşleştirmek gerekir.

### JKU Parametresi ile Kendinden İmzalı JWT'leri Enjekte Etme

Bazı sunucular,

jwk

başlık parametresi yerine

jku

(JWK Set URL) başlık parametresini kullanarak, anahtar setini içeren bir URL referansına izin verirler. İmza doğrulanırken sunucu bu URL'den ilgili anahtarı alır.

JWK Set Nedir?

JWK Set, farklı anahtarları temsil eden bir JWK'lerin dizisini içeren bir JSON nesnesidir.

Örnek:

```auto
{
    "keys": [
        {
            "kty": "RSA",
            "e": "AQAB",
            "kid": "75d0ef47-af89-47a9-9061-7c02a610d5ab",
            "n": "o-yy1wpYmffgXBxhAUJzHHocCuJolwDqql75ZWuCQ_cb33K2vh9mk6GPM9gNN4Y_qTVX67WhsN3JvaFYw-fhvsWQ"
        },
        {
            "kty": "RSA",
            "e": "AQAB",
            "kid": "d8fDFo-fS9-faS14a9-ASf99sa-7c1Ad5abA",
            "n": "fc3f-yy1wpYmffgXBxhAUJzHql79gNNQ_cb33HocCuJolwDqmk6GPM4Y_qTVX67WhsN3JvaFYw-dfg6DH-asAScw"
        }
    ]
}
```

Bu anahtar setleri bazen

/jwks.json

veya

/.well-known/jwks.json

gibi standart uç noktalar üzerinden public olarak sunulur.

### KID Parametresi ile Kendinden İmzalı JWT'leri Enjekte Etme

Sunucular, yalnızca JWT'ler değil, farklı türde verileri imzalamak için de birçok kriptografik anahtar kullanabilirler. Bu nedenle, bir JWT'nin başlığı

kid

(Key ID) parametresini içerebilir. Bu parametre, imzanın doğrulanması için hangi anahtarın kullanılacağını belirler.

Saldırı Adımları

Eğer

kid

parametresi dizin geçişine karşı savunmasızsa, saldırgan sunucunun doğrulama anahtarı olarak dosya sisteminden rastgele bir dosyayı kullanmasını sağlayabilir. (Path Traversal)

```auto
{
    "kid": "../../path/to/file",
    "typ": "JWT",
    "alg": "HS256",
    "k": "asGsADas3421-dfh9DGN-AFDFDbasfd8-anfjkvc"
}
```

Bu özellikle sunucu simetrik algoritmalarla imzalanmış JWT'leri de destekliyorsa tehlikelidir. Bu durumda, saldırgan

kid

parametresini tahmin edilebilir statik bir dosyaya işaret edebilir ve bu dosyanın içeriğine uygun bir gizli anahtarla JWT'yi imzalayabilir.

Eğer sunucu doğrulama anahtarlarını bir veritabanında saklıyorsa, kid başlık parametresi SQL injection saldırıları için de bir saldırı vektörü olabilir.

### Diğer İlginç JWT Başlık Parametreleri

- **cty (Content Type):** JWT payloadında içeriğin medya türünü belirtmek için kullanılır. Genellikle başlıktan çıkarılır, ancak yazılımda kullanılan kütüphane yine de destekleyebilir. İmza doğrulamasını atlatmanın bir yolunu bulduysanız,
    
    cty
    
    başlığını enjekte ederek içerik türünü
    
    auto terminal title=""/xml
    
    veya
    
    application/x-java-serialized-object
    
    olarak değiştirmeyi deneyebilirsiniz. Bu,
    
    XXE
    
    ve
    
    serileştirme saldırıları
    
    için yeni vektörler açabilir.
    
- **x5c (X.509 Certificate Chain):** JWT'yi dijital olarak imzalamak için kullanılan anahtarın X.509 genel anahtar sertifikasını veya sertifika zincirini iletmek için kullanılır. Bu başlık parametresi, kendinden imzalı sertifikaları enjekte etmek için kullanılabilir. X.509 formatının ve uzantılarının karmaşıklığı nedeniyle, bu sertifikaların ayrıştırılması da güvenlik açıklarına neden olabilir.
