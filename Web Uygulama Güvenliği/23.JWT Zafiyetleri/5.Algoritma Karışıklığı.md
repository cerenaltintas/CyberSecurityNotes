JWT (JSON Web Token) güvenliğini tehlikeye atan yaygın saldırılardan biri, algoritma karışıklığı saldırısıdır. Bu saldırıda, JWT'nin imzalama algoritmasının yanlış yapılandırılması veya kötüye kullanılması söz konusudur. Bu bölümde, algoritma karışıklığının ne olduğunu, nasıl istismar edildiğini ve bu saldırılara karşı nasıl korunabileceğimizi inceleyeceğiz.

Algoritma karışıklığı saldırıları, saldırganın bir JWT'nin imzasını, web sitesi geliştiricilerinin beklediğinden farklı bir algoritma kullanarak doğrulaması için sunucuyu yanılttığı durumlarda meydana gelir. Bu durum düzgün bir şekilde ele alınmazsa, saldırganların sunucunun gizli imzalama anahtarını bilmeden geçerli JWT'ler oluşturmasına olanak tanır.

### Simetrik ve Asimetrik Algoritmalar

JWT'ler, farklı algoritmalar kullanılarak imzalanabilir.

- **Simetrik Algoritmalar (örn. HS256):** Hem imzalama hem de doğrulama için aynı anahtar kullanılır. Bu anahtar, bir şifre gibi gizli tutulmalıdır.
    
- **Asimetrik Algoritmalar (örn. RS256):** Bir özel anahtar imzalama için, bir genel anahtar ise doğrulama için kullanılır. Genel anahtar paylaşılabilir, özel anahtar ise gizli tutulmalıdır.
    

### Algoritma Karışıklığı Zafiyetleri Nasıl Oluşur?

Algoritma karışıklığı zafiyetleri, JWT kütüphanelerinin hatalı uygulanması nedeniyle ortaya çıkar. Birçok kütüphane, imza doğrulama için

alg

parametresine dayanarak algoritma seçimi yapar. Bu, geliştiricilerin belirli bir algoritmanın kullanılacağını varsaydığında sorun yaratabilir.

Örneğin, aşağıdaki basitleştirilmiş örnek kodda, imza doğrulama işlemi hem RS256 hem de HS256 algoritmaları için yapılmaktadır:

```auto
def verify(token, secretOrPublicKey):
    algorithm = token.getAlgHeader()
    if algorithm == "RS256":
        # Sağlanan anahtarı RSA genel anahtarı olarak kullan
    elif algorithm == "HS256":
        # Sağlanan anahtarı HMAC gizli anahtarı olarak kullan
```

Eğer geliştiriciler, sunucunun yalnızca

RS256

ile imzalanmış tokenlari kabul edeceğini varsayıp her zaman sabit bir genel anahtar kullanıyorsa, saldırganlar tokeni

HS256

ile imzalayıp, bu genel anahtarı

HMAC

gizli anahtarı olarak kullanarak doğrulama işlemini atlatabilirler.

### Algoritma Karışıklığı Saldırısının Gerçekleştirilmesi

Algoritma karışıklığı saldırısı genellikle aşağıdaki adımları içerir.

**1. Sunucunun Genel Anahtarını (Public Key) Elde Edin:** Bu anahtar genellikle

/jwks.json

veya

/.well-known/jwks.json

gibi standart bir uç noktada bulunabilir.

**2. Genel Anahtarı Uygun Bir Formata Dönüştürün:** Elde edilen JWK'yı (JSON Web Key) gerekli formata (örn. PEM) dönüştürün.

**3. Kötü Amaçlı Bir JWT Oluşturun:** Payload'u ve

alg

başlığını değiştirin,

HS256

olarak ayarlayın.

**4. Token'i HS256 ile İmzalayın:** Genel anahtarı gizli anahtar olarak kullanarak tokeni imzalayın.

Adım 1: Sunucunun Genel Anahtarını Elde Etme

Sunucular bazen genel anahtarlarını JSON Web Key (JWK) nesneleri olarak standart bir uç noktada saklarlar. Örneğin:

```auto
{
  "keys": [
    {
      "kty": "RSA",
      "e": "AQAB",
      "kid": "75d0ef47-af89-47a9-9061-7c02a610d5ab",
      "n": "o-yy1wpYmffgXBxhAUJzHHocCuJolwDqql75ZWuCQ_cb33K2vh9mk6GPM9gNN4Y_qTVX67WhsN3JvaFYw-fhvsWQ"
    }
  ]
}
```

Adım 2: Genel Anahtarı Uygun Bir Formata Dönüştürme

Genel anahtarı JWK formatından

X.509 PEM

formatına dönüştürmek için

JWT Editor

uzantısını kullanabilirsiniz:

1. Burp Suite'in JWT Editor Keys sekmesine gidin.
2. Yeni bir RSA Anahtarı oluşturun ve JWK'yi yapıştırın.
3. PEM formatına dönüştürün ve bu anahtarı kullanarak imza oluşturun.

Adım 3: Kötü Amaçlı JWT Oluşturma

JWT'nin başlık kısmındaki

alg

parametresini

HS256

olarak değiştirin ve payload'u manipüle edin.

Adım 4: Token'i İmzalayın

Token'i HS256 algoritması ile imzalayın, gizli anahtar olarak genel anahtarı kullanarak:

```auto
import jwt

header = {
    "alg": "HS256",
    "typ": "JWT"
}
payload = {
    "sub": "administrator"
}
token = jwt.encode(payload, "PUBLIC_KEY_AS_SECRET", algorithm="HS256", headers=header)
```

Bu adımları takip ederek uyguladığımız saldırı ile JWT doğrulama sürecini atlatabilir ve yetkisiz erişim sağlayabiliriz.
