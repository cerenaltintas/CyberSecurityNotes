NoSQL Injection, NoSQL veri tabanlarına zararlı verilerin enjekte edilmesi ile gerçekleştirilen saldırılardır. Bu tür saldırılar, NoSQL veri tabanlarının güvenlik açıklarını kullanarak yetkisiz veri erişimi, veri değiştirme veya silme gibi zararlı eylemlerin gerçekleştirilmesine neden olabilir.

### NoSQL Veri Tabanlarının Temel Güvenlik Açıkları

NoSQL veri tabanlarında bazı sık karşılaşılan temel güvenlik açıkları şunlardır:

- **Zayıf Kimlik Doğrulama:** Kullanıcıların kimlik doğrulama süreçlerinin yetersiz olması.
- **Yetersiz Girdi Doğrulama:** Kullanıcı girişlerinin uygun şekilde doğrulanmaması ve filtrelenmemesi.
- **Güvenlik Yapılandırmalarının Eksikliği:** Veri tabanı yapılandırmalarının güvenlik gereksinimlerine uygun olmaması.

### NoSQL Veri Tabanlarının Güvenlik Mekanizmaları

NoSQL veri tabanları, güvenlik açıklarını minimize etmek için çeşitli güvenlik mekanizmalarına sahiptir.

- **Kimlik Doğrulama ve Yetkilendirme:** Kullanıcıların kimliklerinin doğrulanması ve erişim yetkilerinin kontrol edilmesi.
- **Girdi Doğrulama ve Filtreleme:** Kullanıcı girişlerinin doğrulanması ve zararlı girişlerin filtrelenmesi.
- **Şifreleme:** Verilerin şifrelenerek depolanması ve iletilmesi.
- **Güvenlik Denetimleri:** Düzenli olarak güvenlik denetimlerinin yapılması ve güvenlik açıklarının giderilmesi.

### NoSQL Injection Nasıl Çalışır?

NoSQL Injection saldırıları, genellikle kullanıcı girişlerinin doğrulanmaması veya filtrelenmemesi sonucu gerçekleşir. Saldırganlar, zararlı verileri veri tabanına enjekte ederek sorguları manipüle eder ve yetkisiz işlemler gerçekleştirir.

### NoSQL Injection Türleri ve Teknikleri

NoSQL Injection saldırıları, çeşitli tekniklerle gerçekleştirilebilir.Bu teknikler, NoSQL veri tabanlarının farklı özelliklerini ve zafiyetlerini kullanarak zararlı sorguların nasıl enjekte edilebileceğini gösterecektir.

1. String Manipülasyonları

String manipülasyonları, NoSQL Injection saldırılarında yaygın olarak kullanılır. Bu teknik, kullanıcı girişlerinin doğru şekilde doğrulanmaması durumunda veritabanına zararlı stringler enjekte edilerek gerçekleştirilir.

**Örnek:** MongoDB'de string manipülasyonu ile NoSQL Injection

Aşağıdaki örnekte, MongoDB'de bir kullanıcı doğrulama sorgusunun nasıl manipüle edilebileceğini göreceğiz:

```auto
// Güvenlik açığı bulunan sorgu
db.users.find({ "username": "admin", "password": "password123" });

// Zararlı girdi ile manipüle edilmiş sorgu
db.users.find({ "username": "admin' || '1'=='1", "password": "password123" });
```

Bu durumda, saldırgan "username" alanına

admin' || '1'=='1

girdiğini varsayalım. Bu girdi, MongoDB sorgusunda

1=='1

ifadesi her zaman doğru olduğu için tüm kullanıcı kayıtları dönebilir.

2. Boolean Manipülasyonları

Boolean manipülasyonları, NoSQL sorgularında boolean değerlerin manipüle edilmesiyle gerçekleştirilir. Bu teknik, kullanıcı girişlerinin doğru şekilde doğrulanmaması durumunda kullanılabilir.

**Örnek:** MongoDB'de boolean manipülasyonu ile NoSQL Injection

```auto
// Güvenlik açığı bulunan sorgu
db.users.find({ "username": "admin", "password": "password123" });

// Zararlı girdi ile manipüle edilmiş sorgu
db.users.find({ "username": "admin", "password": { "$ne": null } });
```

Bu durumda, saldırgan "password" alanına

{ "$ne": null }

girdiğini varsayalım. Bu girdi, MongoDB sorgusunda

"password": { "$ne": null }

ifadesine dönüşür ve bu ifade her zaman doğru olduğu için tüm kullanıcı kayıtları dönebilir.

3. Object Manipülasyonları

Object manipülasyonları, NoSQL sorgularında nesne (object) değerlerinin manipüle edilmesiyle gerçekleştirilir. Bu teknik, özellikle MongoDB gibi belge odaklı veri tabanlarında yaygındır.

4. Array Manipülasyonları

Array manipülasyonları, NoSQL sorgularında dizi (array) değerlerinin manipüle edilmesiyle gerçekleştirilir. Bu teknik, özellikle MongoDB gibi belge odaklı veri tabanlarında yaygındır.
