**Object Injection (Nesne Enjeksiyonu)**, bir uygulamanın, kullanıcılardan alınan verileri doğrudan bir nesnenin özelliklerine atadığı süreçte ortaya çıkan bir güvenlik açığıdır. Bu tür bir zafiyet, saldırganların uygulama nesnelerine istenmeyen veya zararlı değerler atamasına olanak tanır. Bu, uygulamanın iş mantığını bozabilir, yetkisiz erişim sağlayabilir veya diğer güvenlik zafiyetlerini tetikleyebilir.

**Mass Assignment (Toplu Atama)**, kullanıcıdan alınan verilerin doğrudan bir nesnenin birçok özelliğine atanması sürecidir. Bu yöntem, kullanıcı tarafından gönderilen tüm parametrelerin bir nesneye atanmasına olanak tanır. Eğer uygulama, hangi alanların atanabileceğini açıkça belirlemezse, saldırganlar, istenmeyen alanlara da değer atayarak güvenlik açıklarından yararlanabilirler.

### Object Injection ve Mass Assignment'in Riskleri

- **Yetkisiz Erişim ve Yetki Yükseltme:** Saldırganlar, kullanıcı nesnelerine yönetici yetkileri veya diğer özel yetkiler atayabilir.
- **Veri Manipülasyonu:** Saldırganlar, kritik veri alanlarını manipüle ederek sistemin işleyişini bozabilir.
- **Güvenlik Zafiyetlerinin Tetiklenmesi:** Saldırganlar, enjeksiyon saldırıları veya diğer güvenlik açıklarını tetiklemek için nesne özelliklerini kötüye kullanabilir.

### Object Injection ve Mass Assignment Örnekleri

Kullanıcı Kayıt Formu Örneği

Aşağıdaki gibi bir kullanıcı kayıt formu düşünelim.

```auto
<form action="/register" method="POST">
  <input type="text" name="username">
  <input type="password" name="password">
  <input type="email" name="email">
  <input type="submit" value="Register">
</form>
```

Backend'de bu form verileri aşağıdaki gibi doğrudan kullanıcı nesnesine atanıyor olabilir.

```auto
user = User(params)
```

Saldırgan, formu manipüle ederek

is_admin

gibi olası veri alanlarına değer atayarak sunucuya istek gönderebilir ve kendisine yönetici yetkileri atayabilir.

PHP Object Injection Örneği

PHP'de nesne enjeksiyonu ile ilgili aşağıdaki gibi bir örnek uygulama düşünelim.

```auto
class User {
    public $username;
    public $password;
    public $is_admin = false;
}

$data = $_POST['user_data'];
$user = new User();
foreach ($data as $key => $value) {
    $user->$key = $value;
}
```

Saldırgan, normal şartlarda gönderilen

username

ve

password

parametrelerini manipüle ederek

is_admin

parametresi ekleyebilir.

Bu durumda,

$user->is_admin

değeri

true

olarak ayarlanır ve saldırgan yetkisiz erişim elde etmiş olur.

### Object Injection ve Mass Assignment'e Karşı Korunma Yöntemleri

Güvenli Atama Yöntemleri Kullanmak

Yalnızca belirli alanların atanmasını sağlamak.

```auto
user = User(username=params['username'], password=params['password'], email=params['email'])
```

White-listing

Atanabilir alanları belirlemek ve yalnızca bu alanlara izin vermek.

```auto
params.require(:user).permit(:username, :password, :email)
```

Black-listing

Güvenli olmayan alanları belirleyip bunlara izin vermemek, ancak bu yaklaşım white-listing kadar güvenli değildir.

ORM Özelliklerini Kullanmak

ORM (Object-Relational Mapping) özelliklerini kullanarak güvenli atamaları sağlamak.

```auto
class User < ApplicationRecord
  attr_accessor :username, :password, :email
  attr_protected :is_admin
end
```
