Server-Side Template Injection (SSTI) zafiyetinin temel nedeni, kullanıcıdan gelen ve temizlenmemiş (unsanitized) verilerin doğrudan sunucu tarafındaki şablon motorunun işleyeceği şablon dizesinin (template string) bir parçası haline getirilmesidir. Bu bölümde, Python (Flask/Jinja2) ve PHP (Twig) dillerinde bu hatanın nasıl yapıldığını ve nasıl düzeltileceğini inceleyeceğiz.

### Python (Flask & Jinja2) Zafiyetli Örnek

Flask, Jinja2'yi varsayılan şablon motoru olarak kullanan popüler bir Python web framework'üdür. SSTI, genellikle

render_template_string

fonksiyonunun yanlış kullanılmasıyla ortaya çıkar.

**Zafiyetli Kod:** Aşağıdaki Flask uygulaması, URL'den aldığı

name

parametresini doğrudan bir dize içinde birleştirerek şablon motoruna gönderir.

app.py

```auto
from flask import Flask, request, render_template_string

app = Flask(__name__)

@app.route('/profile')
def profile():
    # KULLANICIDAN GELEN GİRDİ
    name = request.args.get('name', 'Guest')

    # ZAFİYETLİ KULLANIM: Kullanıcı girdisi, şablonun bir parçası haline geliyor.
    # render_template_string fonksiyonu tüm dizeyi işler.
    template = f"<h1>Hoş Geldin, {name}!</h1>"

    return render_template_string(template)

if __name__ == '__main__':
    app.run(debug=True)
```

**Neden Zafiyetli?** Buradaki sorun,

name

değişkeninin (kullanıcı girdisi) f-string kullanılarak doğrudan şablon dizesine eklenmesidir.

render_template_string

fonksiyonu, bu birleştirilmiş dizeyi bir bütün olarak işler. Eğer bir saldırgan

name

parametresi olarak

{{7*7}}

gönderirse, fonksiyonun işleyeceği dize

"<h1>Hoş Geldin, {{7*7}}!</h1>"

olur. Jinja2, bu dize içindeki

{{7*7}}

ifadesini bir şablon komutu olarak görür, çalıştırır ve

49

sonucunu döndürür.

**Güvenli Kod:** Güvenli yaklaşım, şablonu ve veriyi her zaman ayrı tutmaktır. Jinja2'nin otomatik "escaping" (kaçış) özelliğinden faydalanmak için

render_template

veya

render_template_string

fonksiyonlarına veriler ayrı bir context (bağlam) nesnesi olarak geçirilmelidir.

app.py (Güvenli)

```auto
from flask import Flask, request, render_template

app = Flask(__name__)

# Güvenli yöntemde, şablon ayrı bir dosyada tutulur.
# templates/profile.html -> <h1>Hoş Geldin, {{ name }}!</h1>

@app.route('/profile')
def profile():
    name = request.args.get('name', 'Guest')

    # GÜVENLİ KULLANIM: Veri, şablona bir bağlam olarak geçirilir.
    # Jinja2, 'name' değişkenini bir komut olarak değil, sadece bir dize olarak işler.
    return render_template('profile.html', name=name)
```

Bu yöntemde,

{{ name }}

ifadesi her zaman güvenli bir şekilde işlenir.

{{7*7}}

gibi bir girdi gönderilse bile, Jinja2 bunu bir komut olarak çalıştırmaz ve ekrana

{{7*7}}

olarak basar.

### PHP (Twig) Zafiyetli Örnek

Twig, PHP için popüler ve güvenli bir şablon motorudur. Ancak, yanlış kullanıldığında SSTI zafiyetine yol açabilir. Zafiyet, genellikle

createTemplate

metodunun

render

ile birlikte güvensiz bir şekilde kullanılmasından kaynaklanır.

**Zafiyetli Kod:** Aşağıdaki PHP kodu, kullanıcıdan aldığı

name

girdisini doğrudan

createTemplate

içine yerleştirir.

index.php

```auto
<?php
require_once 'vendor/autoload.php';

$loader = new \Twig\Loader\ArrayLoader();
$twig = new \Twig\Environment($loader);

// KULLANICIDAN GELEN GİRDİ
$name = $_GET['name'] ?? 'Guest';

// ZAFİYETLİ KULLANIM: Kullanıcı girdisi, şablonun bir parçası yapılıyor.
$templateString = "<h1>Hoş Geldin, " . $name . "!</h1>";
$template = $twig->createTemplate($templateString);

echo $template->render();
?>
```

**Neden Zafiyetli?** Tıpkı Flask örneğinde olduğu gibi,

$name

değişkeni (kullanıcı girdisi) şablon dizesiyle birleştirilir.

createTemplate

metodu, bu birleştirilmiş dizeyi işlenecek bir şablon olarak derler. Eğer saldırgan

name

parametresi olarak

{{7*7}}

gönderirse, derlenecek olan şablon

"<h1>Hoş Geldin, {{7*7}}!</h1>"

olur. Twig bu ifadeyi çalıştırır ve

49

sonucunu üretir.

**Güvenli Kod:** Doğru yaklaşım, şablonu ve veriyi ayrı tutmaktır. Şablon, değişkenleri yer tutucu olarak içermeli ve

render

metoduna veriler bir dizi olarak geçirilmelidir.

index.php (Güvenli)

```auto
<?php
require_once 'vendor/autoload.php';

$loader = new \Twig\Loader\ArrayLoader([
    'profile' => '<h1>Hoş Geldin, {{ name }}!</h1>',
]);
$twig = new \Twig\Environment($loader);

$name = $_GET['name'] ?? 'Guest';

// GÜVENLİ KULLANIM: Veri, render metoduna bir dizi olarak geçirilir.
// Twig, 'name' değişkenini güvenli bir şekilde işler.
echo $twig->render('profile', ['name' => $name]);
?>
```

Bu kullanımda,

name

değişkenine

{{7*7}}

atansa bile, Twig bunu bir komut olarak yorumlamaz ve varsayılan olarak HTML kaçış işlemine tabi tutarak güvenli bir şekilde ekrana basar.
