Result-based Command Injection, bir uygulamanın kullanıcı girdisini doğrulamadan işletim sistemi komutu olarak çalıştırmasıyla ortaya çıkan zafiyettir. Bu tür saldırılarda saldırgan, komut çıktısını, sonucunu doğrudan görebilir ve işlemin sonucunu doğrulayabilir.

**Örnek Senaryo:**

```auto
<?php

$user_command = $_GET['cmd'];

system($user_command);
?>
```

Bu PHP kodu, bir web isteği üzerinden

cmd

parametresi ile gönderilen kullanıcı komutunu doğrudan

system

fonksiyonu aracılığıyla işletim sistemine iletir ve çalıştırır, bu da potansiyel olarak güvenlik açıklarına yol açabilir.

Saldırgan URL'ye

?cmd=ls

eklerse, sunucudaki dosyaların listesini görebilir. Daha tehlikeli komutlarla sistemde yetkisiz işlemler yapabilir.

### Result-based Command Injection Saldırısı Örneği:

Uygulamanın İncelenmesi

DNS kayıtlarını sorgulayan ve sonucu ekrana bastıran **DNS Lookup** uygulaması incelenmektedir. DNS kayıtlarını sorgulamak için işletim sisteminde kurulu olan bir aracın (dig, nslookup vb.) kullanılma ihtimali düşünülerek Command Injection zafiyetinin varlığı değerlendirilmektedir.

![](https://storage.hackviser.com/file/hackviser-prod/trainings/sections/images/fc8bab35-73d3-4bdd-9611-7ffb268803b3/result-based-query-222a37958.webp)

Öncelikle uygulamanın işleyişini görmek amacıyla

google.com

adresi sorgulanmıştır. Sonucun sayfa içerisinde bastırıldığı görülmektedir.

```auto
┌─[root@hackerbox]─[~]
└──╼ #nslookup google.com
Server:		172.20.3.1
Address:	172.20.3.1#53

Name:	google.com
Address: 142.250.181.238
Name:	google.com
Address: 2a00:1450:4001:82f::200e
```

Merak edilip Linux işletim sisteminde bulunan DNS kayıt sorgulama araçları ile aynı adres sorgulandığında

nslookup

aracı ile benzer bir sonuca ulaşıldığı görülmektedir. Bu durum potansiyel bir Command Injection zafiyetinin varlığına işaret etmektedir.

Zafiyetin Tespit Edilmesi

![](https://storage.hackviser.com/file/hackviser-prod/trainings/sections/images/fc8bab35-73d3-4bdd-9611-7ffb268803b3/result-based-whoami-252ff77bd.webp)

Adres girişinde shell komutu barındıran

; whoami

payload ile bir deneme yapılmıştır. Burada

;

ile uygulama içerisinde bulunan sistem komutlarının çalışmasının ardından payload içerisindeki komutun çalışması sağlanmıştır.

whoami

ise uygulamanın yetkisini kullanarak çalıştığı kullanıcının adıdır. Burada

www-data

olduğu görülmektedir.

**www-data**, genellikle web sunucusu yazılımlarının çalıştırdığı işlemlere ayrılmış, sınırlı izinlerle yapılandırılmış bir kullanıcıdır ve bu sayede web uygulamalarında güvenlik amacıyla kullanılır.

Bu aşamada birçok payload çeşidi denenebilir:

; whoami

,

google.com; whoami

,

| whoami

,

&& whoami

,

|| whoami

İncelemelerin ardından yapılan tahminlere göre uygulamanın işletim sisteminde çalıştırdığı komut muhtemel olarak şu şekilde gözükecektir:

nslookup ; whoami

![](https://storage.hackviser.com/file/hackviser-prod/trainings/sections/images/fc8bab35-73d3-4bdd-9611-7ffb268803b3/result-based-ls-f493a05fe.webp)

Burada da

; ls

payload'u içerisinde bulunan

ls

komutu kullanılmıştır. Bulunulan dizin içerisindeki dosya ve dizinler listelenmiştir.

Bu aşamada Command Injection zafiyetinin varlığı kesinlikle doğrulanmış olunup işletim sistemi üzerinde izin verilen yetkiler ile istenilen işlemin yapılabileceği görülmektedir.

![](https://storage.hackviser.com/file/hackviser-prod/trainings/sections/images/fc8bab35-73d3-4bdd-9611-7ffb268803b3/result-based-ampersand-ls-897d7555d.webp)

Ekstra olarak farklı bir payload ile de deneme yapılmıştır. Burada da önceki komut başarılı ise diğerini çalıştır anlamına gelen operatör

&&

kullanılmıştır. Önce google.com için DNS sorgulaması yaparak sonrasında

ls

komutunu çalıştırmıştır.

```auto
google.com && ls
```

![](https://storage.hackviser.com/file/hackviser-prod/trainings/sections/images/fc8bab35-73d3-4bdd-9611-7ffb268803b3/result-based-pipe-whoami-8fb071ede.webp)

Burada ise

||

kullanarak zafiyet tetiklenmeye çalışılmıştır.

||

dan önceki komut girdi verilmediği için başarısız olduğundan dolayı, ikinci komut çalıştırılmıştır.

```auto
|| whoami
```

### Kaynak Kod Analizi

Zafiyetin temel sebebi, kullanıcı tarafından gönderilen bir değeri doğrudan

nslookup

komutunda kullanmaktadır. Bu kod parçası, kullanıcı girdisini doğrudan ve kontrolsüz bir şekilde işletim sistemi komutlarına eklediği için Command Injection saldırılarına açık bir yapıdadır.

Zafiyetli Kod Örneği

```auto
<?php
  if (isset($_POST['query'])) {
    $query = $_POST['query'];

    $command = "nslookup $query"; // Vulnerable
    exec($command, $output); // Vulnerable

    if (!empty($output)) {
      echo '<div class="mt-3 mb-5 p-4" style="background-color:#f7f7f9;border-radius:13px;">';

      foreach ($output as $line) {
        echo '<code>' . htmlspecialchars($line) . '</code><br>';
      }

      echo '</div>';
    }
  }
?>
```

```auto
  $command = "nslookup $query"; // Vulnerable
  exec($command, $output); // Vulnerable
```

Bu kodda,

POST

metodu ile alınan

query

parametresi, herhangi bir güvenlik önlemi alınmadan doğrudan

nslookup

komutunda kullanılıyor. Eğer "query" parametresi olarak

google.com; whoami

gibi bir komut gönderilirse, bu komut kullanıcının işletim sisteminde çalıştırılabilir, bu da sistemin zarar görmesine neden olabilir.

Güvenli Kod Örneği

```auto
<?php
  if (isset($_POST['query'])) {
    $query = $_POST['query'];

    $safe_query = escapeshellarg($query); // Protection

    $command = "nslookup $safe_query";
    exec($command, $output);

    if (!empty($output)) {
      echo '<div class="mt-3 mb-5 p-4" style="background-color:#f7f7f9;border-radius:13px;">';

      foreach ($output as $line) {
        echo '<code>' . htmlspecialchars($line) . '</code><br>';
      }

      echo '</div>';
    }
  }
?>
```

```auto
  $safe_query = escapeshellarg($query); // Protection

  $command = "nslookup $safe_query";
  exec($command, $output);
```

Bu kodda,

escapeshellarg()

fonksiyonu kullanılarak kullanıcı girdisi işletim sistemi komutları içinde güvenli bir şekilde kullanılmaktadır. Bu fonksiyon, alınan girdiyi bir komut argümanı olarak kullanılmak üzere uygun şekilde kaçış işlemi uygular, "query" parametresi içindeki potansiyel zararlı girdiler, zararsız hale getirilerek Command Injection saldırıları engellenmiş olur.
