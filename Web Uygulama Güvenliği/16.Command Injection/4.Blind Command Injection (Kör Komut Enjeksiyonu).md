Blind Command Injection, saldırganın doğrudan komut çıktısını göremediği diğer bir ifadeyle kör bir şekilde çalıştığı ancak komutun başarıyla çalıştığını farklı yollarla anlayabildiği saldırı türüdür. Bu tür saldırılarda, çıktıyı doğrudan elde edemeyen saldırganlar, alternatik yöntemler (örneğin, sunucu yanıt süresi, hata mesajları veya harici bir işlem) ile komutun etkisini anlamaya çalışır.

**Örnek Senaryo:**

```auto
<?php

$host = $_GET['host'];

$ping_result = shell_exec("ping -c 1 " . $host);

if (strpos($ping_result, '1 packets received') !== false) {
    echo "Host is accessible!";
} else {
    echo "Host is unreachable!";
}
?>
```

Bu PHP kodu,

$_GET

aracılığıyla HTTP isteğinde gelen

host

parametresini alır ve

shell_exec

fonksiyonunu kullanarak bu girdiyi bir

ping

komutu içinde işletim sistemine iletir. Komutun çıktısını analiz ederek,

1 packets received

dizesini içerip içermediğini kontrol eder. Eğer içeriyorsa, "Host is accessible!" mesajını, içermiyorsa "Host is unreachable!" mesajını kullanıcıya gösterir. Ancak, bu yaklaşım kullanıcı girdisini doğrulamadığı için komut enjeksiyonu saldırılarına karşı savunmasızdır.

Saldırgan,

; sleep 10

komutunu ekleyerek sunucunun yanıt süresini manipüle edebilir. Sunucu 10 saniye yanıt vermezse, saldırgan komutun çalıştığını dolaylı olarak anlar. Alternatif bir yöntem ile saldırgan, hedefin kendi sunucusuna istek atmasını sağlayarak zafiyetin varlığını öğrenebilir.

### Blind Command Injection Saldırısı Örneği:

Uygulamanın İncelenmesi

Ziyaretçi kayıtlarını tutmak amacıyla tarayıcının **User Agent** bilgisini saklayan bir web uygulaması incelenmektedir. Bu bilginin saldırganların manipüle edebileceği HTTP başlıklarının içerisinde bulunan

User-Agent

başlığından alındığı ve işlendiği ihtimali düşünülerek Command Injection zafiyetinin varlığı değerlendirilmektedir.

![](https://storage.hackviser.com/file/hackviser-prod/trainings/sections/images/9cc5b793-3ad5-443a-946a-0dacb19b7106/blind-web-home-page-c39cafec2.webp)

Öncelikle uygulamanın ana sayfası ziyaret edilmiş olunup, **User Agent** bilgilerinin saklandığına dair bir mesaj olduğu görülmektedir.

![](https://storage.hackviser.com/file/hackviser-prod/trainings/sections/images/9cc5b793-3ad5-443a-946a-0dacb19b7106/blind-burpsuite-useragent-8d6b9ad01.webp)

```auto
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.6367.118 Safari/537.36
```

Burp Suite Web Proxy aracı ile web uygulamasına gönderilen HTTP içeriği incelenmiştir.

Burada gönderilen herhangi bir Command Injection payload'u ve shell komutunun (whoami, hostname, ls) sonucuna dair bir bilginin içeriğin içerisinde bastırılmadığı görülmektedir. Zafiyetin varlığını anlamak için Burp Suite içerisinde sağ alt kısımda bulunan HTTP yanıt süresini (Response Time) ele alınacaktır.

Bu web uygulaması için standart bir HTTP isteğinin yanıt süresinin **176 millis** yani **176 milisaniye** olduğu yapılan bir istek ile görülmektedir. Bu değer istek içeriği, internet hızı ve sunucu kapasitesi gibi bir çok faktöre bağlı olarak değişebilmektedir.

Zafiyetin Tespit Edilmesi

![](https://storage.hackviser.com/file/hackviser-prod/trainings/sections/images/9cc5b793-3ad5-443a-946a-0dacb19b7106/blind-burpsuite-useragent-sleep-4c59ca487.webp)

```auto
User-Agent: '; sleep 10'
```

Zafiyetin varlığını tespit aşamasında

User-Agent

başlığının manipüle edilecektir. Burada bulunan tarayıcı bilgisi silinmiştir. Yanıt süresini artırmak amacıyla işlemi belirli bir süre boyunca durdurup bekleten

sleep

komutu kullanılmıştır.

'; sleep 10'

payload'u içerisinde başında ve sonunda tırnak (') işaretleri kullanılarak yazılım içerisinde kullanılan bir tırnak işaretinin kapatılması sağlanmıştır.

;

ile uygulama içerisinde bulunan sistem komutlarının çalışmasının ardından payload içerisindeki komutun çalışması sağlanmıştır. Bu aşamada tırnak barındıran, barındırmayan veya başka özel karakterler içeren birçok payload çeşidi denenebilir.

Arka planda

"echo '$userAgent' >> ./logs/user_agent.log"

gibi bir kod olduğu tahmin edilerek bu işlem gerçekleştirilmiştir. Payload bu kodun içerisine geldiğinde şu şekilde görünecektir:

"echo ' '; sleep 10' ' >> ./logs/user_agent.log"

Enjekte edilen sistem komutu çalıştırıldığında işlemin 10 saniye gecikmeli olarak çalışması beklenmektedir.

İstek gönderildikten sonra yanıtın gelmesinin en az 10 saniye sürdüğü görülmüştür. Burp Suite içerisindeki HTTP yanıt süresi (Response Time) kısmına bakıldığında **10,250 millis** yani **10.25** saniye olduğu görülmektedir. Bu durumda istenilen bir komutun arka planda çalıştırıldığı sadece çıktısının ekrana bastırılmadığı doğrulanmış olmaktadır. Blind Command Injection zafiyetinin varlığı doğrulanmıştır.

### Kaynak Kod Analizi

Zafiyetin temel sebebi, kullanıcının manipüle edebildiği bir HTTP başlığından doğrulama ve gerekli filtremeleri yapmadan alınan verinin işletim sistemi komutuna direkt olarak dahil edilmesidir.

**client (istemci)** tarafından gönderilen **User-Agent** başlığını kontrol etmeden shell (kabuk) komutuyla dosyaya yazar. Eğer zararlı bir kullanıcı komutu eklenirse, bu komut da doğrudan kabukta çalıştırılır ve sisteme zarar verebilir.

Zafiyetli Kod Örneği

```auto
<?php
  $userAgent = $_SERVER['HTTP_USER_AGENT'];

  $command = "echo '$userAgent' >> ./logs/user_agent.log";

  exec($command);
?>
```

İstemcinin

User-Agent

başlığını

echo

isimli bir komutu işletim sisteminde çalıştırarak bir dosyaya sonuna eklemektedir. Kullanıcı girdisini shell komutu olarak çalıştırdığı için komut enjeksiyonuna açık bir yapıdadır.

Güvenli Kod Örneği

Güvenli bir yaklaşım ile

escapeshellarg()

kullanarak komut enjeksiyon riski azaltılabilir:

```auto
<?php
  $userAgent = $_SERVER['HTTP_USER_AGENT'];

  $safeUserAgent = escapeshellarg($userAgent);

  $command = "echo $safeUserAgent >> ./logs/user_agent.log";

  exec($command);
?>
```

Bu düzenleme ile

User-Agent

başlığı

escapeshellarg

fonksiyonu kullanılarak güvenli bir komut argümanına dönüştürülür. Böylece komut enjeksiyon riskleri minimize edilir.
