SQL enjeksiyonu, kötü niyetli kullanıcıların ya da sızma testi uzmanlarının bir web uygulamasının veritabanı sorgularına zararlı SQL kodları ekleyerek veritabanını manipüle etmeye çalıştığı bir güvenlik zafiyetidir. Bu saldırı yöntemi, web uygulamalarındaki güvenlik açıklarından faydalanarak verilere erişim sağlar, verileri değiştirir veya siler.

### Nasıl Çalışır?

1. **Kullanıcı Girdisi Manipülasyonu:** Saldırgan, uygulamanın kullanıcı girdisi beklediği alanlara (formlar, URL parametreleri vb.) zararlı SQL ifadeleri girer.
2. **Veritabanı Sorgusunun Bozulması:** Bu zararlı girdi, uygulamanın veritabanına yaptığı sorgunun parçası haline gelir. Eğer uygulama bu girdiyi doğru şekilde temizlemezse, orijinal sorgu beklenmedik şekilde değiştirilir.
3. **Yetkisiz Erişim veya Veri Manipülasyonu:** Modifiye edilmiş sorgu, veritabanını yetkisiz sorguları çalıştıracak şekilde manipüle eder. Bu, verilerin çalınması, değiştirilmesi veya yok edilmesiyle sonuçlanabilir.

### SQL Injection Tespit Etmek

Öncelikle, dinamik kullanıcı verileri alan ve bu verileri GET, POST, Cookie parametreleri veya HTTP User-Agent istek başlığı aracılığıyla kabul eden bir web sayfası üzerinde çalıştığınızı varsayalım.

Örnek bir URL:

```auto
http://192.168.136.131/sqlmap/mysql/get_int.php?id=1
```

Bu URL'deki

id

parametresi, SQL enjeksiyonu için potansiyel bir hedeftir.

Aşağıdaki durumları inceleyelim;

**Durum 1**

```auto
http://192.168.136.131/sqlmap/mysql/get_int.php?id=1+AND+1=1
```

**Durum 2**

```auto
http://192.168.136.131/sqlmap/mysql/get_int.php?id=1+AND+1=2
```

Yukarıda bulunan

Durum 1

deki gibi

id

parametresini değiştirerek yaptığımız istek sonucu orijinal sayfa ile aynı içeriği görüyorsak ve

Durum 2

deki gibi

id

parametresini değiştirerek yaptığımız istek sonucunda orijinal sayfadan farklı bir içerik görüyorsak burada bir SQL Injection zafiyetinin varlığından söz edebiliriz.

Şimdi SQL Injection zafiyetine sebebiyet veren durumu açıklayalım. Yukarıdaki yaptığımız istekler sonucu sunucuda çalışan muhtemel bir SQL sorgusu aşağıdaki gibidir.

```auto
sql="SELECT * FROM table WHERE id=" + id_parameter + ";" 
```

Yukarıdaki SQL sorgusunda kullanıcıdan alınan

id_parameter

verisi sorguya direkt olarak dahil edilmekedir. Şimdi bu sorguya kullanıcının gönderdiği **id** parametresini manipüle edilmiş

1 AND 1=1

olarak gönderelim.

```auto
SELECT * FROM table WHERE id=1 AND 1=1;
```

Yukarıdaki sorguda

AND 1=1

koşulu **doğru** sonuç verdiği için eğer SQL Injection zafiyeti varsa yapılan istek sonucunda aynı sayfa görüntülenmelidir.

İkinci adım olarak gönderdiğimiz manipüle edilmiş **id** verisini

1 AND 1=2

olarak gönderelim.

```auto
SELECT * FROM table WHERE id=1 AND 1=2;
```

Yukarıdaki sorguda

AND 1=2

koşulu **yanlış** sonuç verdiği için eğer SQL Injection zafiyeti varsa yapılan istek sonucunda farklı sayfa görüntülenmelidir.

Yapılan bu iki aşamalı doğrulama sonucunda SQL Injection zafiyetinin varlığına karar verilebilir.

### SQL Enjeksiyon Türleri

1. **Tespit Edilebilir (In-band) SQL Enjeksiyonu:** Saldırgan, aynı iletişim kanalı üzerinden hem enjeksiyonu yapar hem de veritabanından veri alır. En yaygın türlerden biri olan 
    
    Error-based
    
     ve 
    
    Union-based
    
     enjeksiyonlar bu kategoriye girer.
2. **Kör (Blind) SQL Enjeksiyonu:** Veritabanından doğrudan veri alınamadığında kullanılır. Saldırgan, uygulamanın davranışındaki değişikliklere dayanarak veritabanı yapısını çıkarmaya çalışır. 
    
    Boolean-based
    
     ve 
    
    Time-based
    
     enjeksiyonlar bu türe örnek gösterilebilir.
3. **Dış Bant (Out-of-band) SQL Enjeksiyonu:** Veri aktarımı ve saldırılar için farklı iletişim kanalları kullanılır. Bu tür, diğer yöntemler işe yaramadığında tercih edilir.

### Korunma Yöntemleri

1. **Girdi Doğrulaması:** Kullanıcı girdilerinin doğru şekilde temizlenmesi ve doğrulanması, zararlı SQL kodlarının sorgulara eklenmesini önler.
2. **Hazırlanmış İfadeler (Prepared Statements):** Bu yöntem, SQL sorgularının yapısını sabit tutar ve enjeksiyonu engeller.
3. **Stored Procedures:** Doğru şekilde kullanıldığında, stored procedures SQL enjeksiyon riskini azaltabilir. Ancak, bu yalnızca prosedürlerin içerisinde dinamik SQL kullanılmadığı durumlar için geçerlidir.
4. **Veritabanı Kullanıcı Ayrıcalıklarını Kısıtlama:** Veritabanı kullanıcılarına yalnızca ihtiyaç duydukları minimum yetkilerin verilmesi, olası bir SQL enjeksiyon saldırısının zararını sınırlayabilir.
