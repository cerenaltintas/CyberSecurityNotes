Race condition zafiyetleri, her biri kendine özgü özellikler ve sonuçlar doğuran çeşitli şekillerde ortaya çıkabilir. Bu bölümde, yaygın race condition türlerini inceleyeceğiz: Data Race, Time-of-Check to Time-of-Use (TOCTOU), Dosya Sistemi Race Conditions ve Bellek Race Conditions.

### Data Race

Data Race, iki veya daha fazla iş parçacığı aynı anda paylaşılan verilere eriştiğinde ve en az bir erişimin yazma işlemi olduğunda ortaya çıkar. Bu durum, çalıştırma sırası garanti edilmediğinden, tutarsız ve öngörülemeyen sonuçlara yol açabilir.

**Örnek**

İki iş parçacığının paylaşılan bir sayacı artırdığını düşünün. Doğru senkronizasyon olmadan, sayaç değeri beklenenden farklı olabilir.

```auto
import threading

counter = 0

def increment():
    global counter
    for _ in range(100000):
        counter += 1

threads = []
for _ in range(2):
    t = threading.Thread(target=increment)
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print(f"Final counter value: {counter}")
```

Bu örnekte, beklenen nihai değer 200000'dir, ancak data race nedeniyle sonuç farklı olabilir.

### Time-of-Check to Time-of-Use (TOCTOU)

TOCTOU zafiyetleri, bir kaynağın bir durum için kontrol edilmesi (time-of-check) ve ardından bu duruma dayanarak kullanılması (time-of-use) durumunda ortaya çıkar. Eğer kaynağın durumu bu iki olay arasında değişirse, güvenlik zafiyetlerine yol açabilir.

**Örnek**

Bir kullanıcının belirli bir işlemi gerçekleştirme yetkisine sahip olup olmadığını kontrol eden bir sistem düşünelim. Kontrol ve işlem arasında kullanıcının yetkisi değişirse, yetkisiz işlem yapılabilir.

```auto
import threading
import time

class User:
    def __init__(self, user_id, is_admin):
        self.user_id = user_id
        self.is_admin = is_admin

    def set_admin(self, is_admin):
        self.is_admin = is_admin

def check_permission_and_execute(user):
    # Check if user is admin
    if user.is_admin:
        # Simulate delay
        time.sleep(1)
        # Execute admin task
        print(f"User {user.user_id} performed an admin task")
    else:
        print(f"User {user.user_id} is not authorized")

# Example usage
user = User(1, True)

# Create threads
threads = []
threads.append(threading.Thread(target=check_permission_and_execute, args=(user,)))

# Change user permission during the check
threads.append(threading.Thread(target=user.set_admin, args=(False,)))

# Start threads
for t in threads:
    t.start()

# Wait for all threads to complete
for t in threads:
    t.join()
```

Bu kod, bir kullanıcının yetkisini kontrol eden ve ardından bir yönetici görevini gerçekleştiren bir sistemde TOCTOU zafiyetini gösterir. Kullanıcının yetkisi kontrol ve görev arasında değişirse, yetkisiz bir işlem yapılabilir. Bu durumu önlemek için işlemler atomik hale getirilmelidir, yani kontrol ve kullanım arasında başka bir işlem gerçekleşememelidir.

### Dosya Sistemi Race Conditions

Dosya Sistemi Race Conditions, birden fazla süreç veya iş parçacığı dosya sistemi nesnelerini aynı anda manipüle ettiğinde ortaya çıkar ve beklenmeyen davranışlara yol açabilir. Bu yarış durumları dosya oluşturma, silme veya değiştirme işlemlerini içerebilir.

**Örnek**

Aynı dosyayı oluşturmaya çalışan iki süreç, tutarsız durumlara veya hatalara yol açabilir.

```auto
import os
import threading

def create_file(filepath):
    if not os.path.exists(filepath):
        with open(filepath, 'w') as file:
            file.write("Hello, world!")

threads = []
filepath = "/tmp/racefile"
for _ in range(2):
    t = threading.Thread(target=create_file, args=(filepath,))
    threads.append(t)
    t.start()

for t in threads:
    t.join()
```

Bu örnekte, her iki iş parçacığı dosyanın varlığını kontrol eder ve ardından dosyayı oluşturmaya çalışır, bu da yarış durumuna yol açar.

### Bellek Yarış Koşulları (Memory Race Conditions)

Birden fazla iş parçacığının (thread) uygun senkronizasyon olmadan paylaşılan belleğe erişip onu değiştirmesi **kayıp güncellemeler**, **veri bozulması** ve **öngörülemez davranışlara** yol açabilir — CPython'da Global Interpreter Lock (GIL) bulunsa bile, bileşik okuma-değiştirme-yazma işlemleri atomik değildir.

**Örnek**

Uygun kilitleme mekanizmaları olmadan paylaşılan bir sayacı artıran iki iş parçacığı:

```auto
import threading

counter = 0

def increment():
    global counter
    for _ in range(100_000):
        counter += 1  # Atomik değil: oku -> değiştir -> yaz

threads = []
for _ in range(2):
    t = threading.Thread(target=increment)
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print(f"Final counter value: {counter}")
```

Uygun senkronizasyon olmadan, **kayıp güncellemeler** nedeniyle son değer beklenen

200000

’den **daha küçük** olabilir.
