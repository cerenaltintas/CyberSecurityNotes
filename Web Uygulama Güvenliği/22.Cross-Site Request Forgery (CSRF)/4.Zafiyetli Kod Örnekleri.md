Bu bölümde, CSRF zafiyetine sahip bir web uygulamasının arka planında çalışan kodun nasıl görünebileceğini inceleyeceğiz. Örnek olarak PHP dilini kullanacağız, çünkü web geliştirmede yaygın olarak kullanılmaktadır.

### PHP'de Zafiyetli E-posta Değiştirme Kodu

Aşağıdaki PHP kodu, bir kullanıcının e-posta adresini değiştirmesini sağlayan basit bir mantık içerir. Ancak, herhangi bir CSRF koruması içermediği için zafiyetlidir.

change_email.php

```auto
<?php
session_start();

// Kullanıcının oturum açıp açmadığını kontrol et
if (!isset($_SESSION['user_id'])) {
    // Oturum yoksa, giriş sayfasına yönlendir
    header('Location: /login.php');
    exit();
}

// Veritabanı bağlantısı varsayılıyor
// include 'db_connection.php';

// Form POST metodu ile gönderildiyse
if ($_SERVER['REQUEST_METHOD'] === 'POST') {

    // Yeni e-posta adresini al
    $new_email = $_POST['email'];
    $user_id = $_SESSION['user_id'];

    // --- ZAFİYETLİ KISIM ---
    // Bu noktada, isteğin gerçekten kullanıcı tarafından mı yapıldığını
    // doğrulayan bir Anti-CSRF token kontrolü YOKTUR.
    // Saldırganın hazırladığı sahte bir formdan gelen istek de,
    // geçerli bir session cookie'si içeriyorsa, kabul edilecektir.

    // E-posta adresini veritabanında güncelle (sözde kod)
    // updateUserEmail($user_id, $new_email);

    echo "E-posta adresiniz başarıyla güncellendi: " . htmlspecialchars($new_email);
    // Genellikle kullanıcı profil sayfasına yönlendirilir
    // header('Location: /profile.php');
    // exit();
}

?>

<!-- E-posta değiştirme formu -->
<form method="POST" action="change_email.php">
    <label for="email">Yeni E-posta Adresiniz:</label>
    <input type="email" id="email" name="email">
    <button type="submit">Güncelle</button>
</form>
```

Zafiyetin Analizi

1. **Oturum Yönetimi Sadece Cookie'ye Dayalı:** Kod, kullanıcının kimliğini doğrulamak için yalnızca 
    
    $_SESSION['user_id']
    
     değerine güveniyor. Bu session, tarayıcıda saklanan bir cookie ile yönetilir.
2. **Anti-CSRF Token Eksikliği:** Kod, POST isteğini işlerken, isteğin kaynağını doğrulayacak benzersiz bir token'ı kontrol etmiyor. 
    
    $_POST['email']
    
     değeri doğrudan alınıp işleme konuluyor.
3. **Tahmin Edilebilir İstek:** Saldırgan, bu formun hangi URL'ye (
    
    change_email.php
    
    ) ve hangi parametrelerle (
    
    email
    
    ) istek gönderdiğini kolayca tahmin edebilir.

Bu üç faktör bir araya geldiğinde, saldırgan, kendi sitesinde barındırdığı ve

action="https://vulnerable-site.com/change_email.php"

adresine sahip bir form ile

vulnerable-site.com

'da oturumu açık olan herhangi bir kullanıcının e-posta adresini değiştirebilir. Sunucu, tarayıcının istekle birlikte gönderdiği session cookie'sini görecek ve isteği gerçek sayacaktır.
